# Asset language and build runtime

The Galois language is a typed recipe graph, not a general-purpose scripting language. TypeScript constructs the graph; Python interprets its materializer operations; Voxeloo supplies native implementations for the expensive voxel and tensor work.

## Generated language contract

The source of truth is the collection of `define_types()` and `define_funcs()` calls under `src/galois/py/assets/defs`. Generated TypeScript exposes:

- literal and derived node shapes;
- converters such as `toStr`, `toI32`, and structured recursive converters;
- typed constructors for every materializer signature;
- runtime type predicates used by exporters and tools.

Do not edit `src/gen/galois/js/lang` directly. Regenerate it with:

```shell
./b ts-deps build
```

When adding or changing a definition:

1. Change the appropriate module under `src/galois/py/assets/defs`.
2. Add or update the exact materializer implementation in `impl/materializers.py`.
3. Add serialization support in `impl/serializers.py` if the value can be a final exported result.
4. Run `./b ts-deps build`; the generator rejects missing or superfluous materializer-map entries.
5. Add TypeScript graph/transport tests and Python materialization/serialization tests.

## Hashing and graph identity

TypeScript hashes literal nodes from materializer kind plus literal data, and derived nodes from materializer kind plus ordered dependency hashes. The hash is used for graph deduplication. Python reconstructs its own node hash for materialization caching after transport.

The hash values are implementation details, but their determinism and semantic inputs are contracts:

- equal recipes must produce equal graph identities;
- changing a literal, operation kind, or dependency order must change identity;
- graph identity must not depend on object address, process order, or platform;
- a hash collision must never silently substitute a different recipe.

Static publication uses a separate MD5 content hash of exported bytes for filenames. Changing graph hashing does not rename an object unless generated bytes change; changing output bytes always produces a new static filename.

## File dependency tracking

Python file helpers record every source path read or checked during a build. Incremental publication hashes those files and associates them with the serialized query. A recipe that bypasses the tracked file helpers can produce stale incremental results.

When adding file access:

- resolve it under the configured Galois data workspace;
- use `impl.repo.open_file()` or `impl.repo.is_file()` where applicable;
- record every optional or variant input that can affect output;
- test create, modify, and delete transitions;
- verify an incremental build matches a clean non-incremental build.

The incremental cache format is an optimization and may be invalidated by bumping its version. It must preserve existing entries on cache hits and tolerate missing or malformed local cache databases by rebuilding.

## Serialization boundary

`impl/serializers.py` and `src/galois/js/interface/types/data.ts` must describe the same tagged values. Important rules include:

- binary payloads use base64 strings across JSON;
- NumPy shapes and coordinate order remain explicit;
- GLTF is JSON text while GLB is binary;
- errors remain distinguishable from valid JSON assets;
- empty geometry and buffers are valid when the corresponding native type permits them;
- native index and tensor encodings must round-trip through their matching reader.

Adding a Python output class without a serializer fails only when that class becomes the final query result. Add an export-level regression test so this cannot remain hidden behind successful intermediate materialization.

## Process and concurrency model

One `BatchAssetServer` processes requests sequentially because its protocol has one ordered response stream. `PoolAssetServer` obtains concurrency by running multiple independent batch workers. Do not allow two requests to interleave on one worker's framing stream.

The runtime resolves its Python interpreter in this order:

1. `BIOMES_ASSET_PYTHON`;
2. the active `VIRTUAL_ENV` interpreter;
3. the repository `.venv` interpreter;
4. shell `python`, with a warning.

Container and packaged-app upgrades must preserve Python dependencies, the Voxeloo extension, source data, and `build.py` at the paths expected by the Node launcher.

## Native boundary

Python imports `voxeloo.galois` for CSG, transforms, sampling, indexes, geometry, groups, lighting, water, and storage buffers. Native changes need both direct C++ tests and pybind boundary tests. A successful Galois Python unit test with a previously installed extension does not prove that the current C++ source builds or exports the expected API.

See [Testing](./testing.md) for the complete cross-language matrix.
